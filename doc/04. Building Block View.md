# 4. Building Block View

## Whitebox Overall System - Level 1

![Whitebox Overall System](./images/Building%20Block%20View%20Diagrams/GesamtBlackboxes.svg)

**Rationale:** We used functional decomposition to separate responsibilities:

- Human Robot Interaction (HRI)
- Global Decision Making
- Manipulation
- Movement
- Computer Vision
- Perception
- Knowledgebase

**Contained Building Blocks:**

| **Building Block**     | **Description**                                                                                          |
|------------------------|----------------------------------------------------------------------------------------------------------|
| HRI                    | Used to interact with the robot                                                                          |
| Global Decision Making | Receives task from HRI; initiates the required steps to fullfill the given task                          |
| Manipulation           | Handles all tasks related to the manipulator and the gripper                                             |
| Movement               | Handles all tasks related to orientation and moving the robot in the environment                         |
| Computer Vision        | Handles object/human detection                                                                           |
| Perception             | Handles LiDAR and Realsense2 camera, aswell as physical input devices such as buttons and microphone     |
| Knowledge Base         | Stores and manages data such as maps and locations (movement) or suitable gripping forces (manipulation) |

### Manipulation - Level 2

![Manipulation Blackbox](./images/Building%20Block%20View%20Diagrams/ManipulationBlackboxes.svg)

**Contained Building Blocks:**

| **Building Block**         | **Description**                                                                                                                          |
|----------------------------|------------------------------------------------------------------------------------------------------------------------------------------|
| Orchestrator               | Coordinates the general tasks of manipulation                                                                                            |
| Gripping Parameter Service | Returns gripping parameters for a given object: gripping force, grip type, grip position and orientation mode, object weight             |
| Processing                 | Calculation and planning of jobs, motions and paths; activation/deactivation of force sensors and force monitor                          |
| Acting                     | Execution of planned movements on the robot arm and gripper                                                                              |
| Force Monitor              | Monitoring of hand force sensors during the manipulaiton process to detect dropped objects                                               |
| Safety                     | Checks for node health; surveils gripping force; surveils surroundings of manipulator; surveils velocity and acceleration of manipulator |

### Manipulation - Level 3

![Manipulation Whitebox](./images/Building%20Block%20View%20Diagrams/ManipulationWhiteboxes.svg)

**Contained Building Blocks (Orchestrator):**

| **Building Block**              | **Description**                                                                |
|---------------------------------|--------------------------------------------------------------------------------|
| Command Splitting               | Divides the joint ManipulationAction for the specific jobs                     |
| Call gripping parameter service | Calls the service to receive the gripping parameters for a given object        |
| Calculate Grasping Point        | Calculates an optimal grasping point for the gripper                           |
| Calculate Placing Point         | Calculates an optimal placing point for an object                              |
| Data Publisher                  | Publishes the data to MoveIt                                                   |

**Contained Building Blocks (Processing):**

| **Building Block**           | **Description**                                                                                                                         |
|------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------|
| Orchestrator Listener        | Subscribes to data published by the orchestrator                                                                                        |
| Job Runner                   | Runs a process or function based on a received command from orchestrator listener; activates/deactivates force sensors and force monitor|
| Plan and Execute             | Plans trajectories and provides execute signals for acting and the force monitoring                                                     |
| MoveIt Init                  | Initializes Move Groub Interfaces for MoveIt                                                                                            |

The hardware interfaces of the manipulator and the gripper are controlled by the **Processing**-Nodes **Plan and Execute**-Functions

### Computer Vision - Level 2

![Computer Vision](./images/Building%20Block%20View%20Diagrams/ComputerVisionWhiteboxes.svg)

**Contained Building Blocks:**

| **Building Block** | **Description** |
|--------------------|-----------------|
| Snapshot Action Server | Accepts goals on `/vision/snapshot`; frames are only processed while a goal is active |
| Model Registry | Loads the YOLO models from `models.yaml`; pinned models stay in memory, others are released after an idle timeout |
| Segmentation and Classification (YOLO) | Runs the selected models on the 2D RGB image, providing classes and segmentation masks |
| Geometry and Entity Mapping | Filters and clusters the point cloud per mask, and maps the label to an entity via `labels.yaml` |
| Knowledge Base Client | Adds the new entities and deletes the pickables they supersede |

All of these live in the single `ObjectDetection` node, so no further decomposition is necessary.

Computer Vision has no local safety node yet, so its health is not reported to the central Safety Node.

### Safety - Level 2

Due to the simple structure of this building block, no further decomposition is necessary. However here follows a brief description of the key concept.

| **Building Block** | **Description**                                                                                                                                                                                                                                                                                         |
|--------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Global Safety Node | This Node is a central control. It is set hierarchical on top of the local safety nodes and has the ability to freeze the system for specific safety critical situations. Additionally this node scans the health state of the system modules by subscribing to the heartbeats of the local safety nodes|
| Local Safety Nodes | These nodes are located inside the modules among the system and are adapted to scan the local tasks for safety issues as described in the chapters above. In case of a system critical issue, the local safety nodes will communicate this occurancy to the central safety node                         |
