## Technical Constraints

| Constraint                    | Explanation                                                                 |
| ----------------------------- | --------------------------------------------------------------------------- |
| **ROS2 middleware**           | All robotic modules must run on ROS2 to ensure interoperability.            |
| **Ubuntu Linux**              | Base operating system (compatibility with ROS2 and hardware drivers).       |
| **NVIDIA Jetson + Intel NUC** | Defined hardware platforms for compute (GPU + CPU workloads).               |
| **Sensors**                   | Use of RGB-D camera, LiDAR, microphones as required by RoboCup @Home tasks. |
| **Languages**                 | Python and C++ as primary programming languages supported in ROS2.          |

## Organizational Constraints

| Constraint                  | Explanation                                                                                                    |
| --------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Semester cycles**         | Work is performed by student groups with limited time per semester.                                            |
| **Shared responsibility**   | Software by University of Augsburg, hardware by AraCom IT Services GmbH, joint architecture planning.          |
| **Resource limitations**    | Budget and hardware availability are limited.                                                                  |
| **Handover between groups** | The system must be designed to allow smooth continuation by future student groups (documentation, modularity). |

## Conventions & Standards

| Constraint                 | Explanation                                                                 |
| -------------------------- | --------------------------------------------------------------------------- |
| **RoboCup @Home rules**    | Competition rules shape the system’s capabilities and setup.                |
| **Coding conventions**     | Adherence to University & AraCom coding guidelines (style, testing, CI/CD). |
| **Safety guidelines**      | Must follow human-robot interaction safety principles.                      |
| **Open source preference** | Preference for open-source software due to cost and academic use.           |
