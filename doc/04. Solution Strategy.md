Manipulation: 
- The orchestrator sends driving and pose commands to MoveIt2 via a publisher/subscriber model
    --> Reason: enables loose coupling between high-level task logic and low-level motion planning, better testing

- MoveIt2 is used for path and motion planning
    --> Reason: well-established framework for collision-aware planning, inverse kinematics, and trajectory generation

- Grip force is determined based on object classification
    --> Reason: Object types are used to adapt grip strength dynamically, reduces the risk of damage or failed grasps
    --> local in manipulation because only the manipulator needs it

- Simulation-based development & validation
    --> All manipulation strategies are first tested in simulation (e.g. Gazebo) because the real robot wasn't ready

Database: 
- Relationale Database
    --> Well-known and proven, Little to no semantic required. 
- Sql-Alchemy 
    --> "Easy" to use,  popular and proven python library, Async Api, has an ORM with support for Python classes

Movement:
- Orchestrator sends movement instructions to the according nodes (e.g. nav2 or SLAM)
- nav2 in conjunction with SLAM is established and has proven to be reliable in the past
