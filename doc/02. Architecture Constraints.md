# 2. Architecture Constraints
<!-- Anything that constrains the team in design and implementation decisions or decision about related processes. Can sometimes go beyond individual systems and are valid for whole organizations and companies. -->

This section outlines the key constraints that limit design and implementation decisions, including technical, organizational, and political factors.

## Technical Constraints

| Use-Case      | Constraints                                                                 |
|---------------|----------------------------------------------------------------------------|
| HRI           | Must run on Jetson Nano (limited processing performance, limited RAM, system reaction time for natural interaction must be acceptable) |
| Manipulation  | Hardware compatibility: must support the selected robotic arm and gripper<br>Real-time performance: motion control and grasping must meet real-time requirements<br>Use of MoveIt2 for motion planning<br>Programming languages: Python & C++ |
| Knowledge Base| Hardware compatibility: must support the Jetson platform<br>Real-time capability: data must be provided with little to no delay<br>Use of SQLAlchemy |
| Movement      | Hardware compatibility: must support robot platform incl. omni-wheels and Jetson<br>Real-time capabilities required for safety<br>Programming language: Python<br>Use of Nav2 & SLAM for navigation and mapping |
| Safety        | Hardware compatibility: must support Jetson platform<br>Real-time capability: safety-critical data must be processed in real-time<br>Emergency Stop: visible, red, easily pressable button only<br>Redundancy: safety must be ensured even if individual components fail<br>Safe human interaction |
