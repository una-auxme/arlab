# 4. Solution Strategy
<!-- Summary of the fundamental decisions and solution strategies that shape the architecture/software. Can include technology, top-level decomposition, approaches to achieve top quality goals and relevant organizational decisions. -->

- **Middleware: ROS2**
  ROS2 was selected as the backbone to ensure interoperability, modularity, and real-time communication between components.
  It provides a widely adopted ecosystem with strong support for robotics, making it the best choice for a sustainable and extensible architecture.

- **Top-level decomposition: Modular architecture**
  The system is split into clear functional domains: perception, computer vision, movement, and manipulation.
  This decomposition supports modularity, extensibility, and maintainability, aligning with the project’s long-term goals.

- **Technology stack**
  - **Python** for fast prototyping and integration.
  - **Docker** for reproducible environments and simplified deployment.
  - **PyTorch** for machine learning and perception tasks.
  - **Gazebo** for simulation and testing in realistic environments.

- **Strategies for quality goals**
  - *Extensibility & Modularity*: ROS2 packages with well-defined interfaces.
  - *Safety*: Hardware emergency stop, fallback behaviors, simulation-based validation.
  - *Robustness*: Continuous testing on both simulation and real hardware.
  - *Real-time performance*: GPU acceleration on Jetson, efficient ROS2 message handling.
  - *Maintainability*: CI/CD pipelines, documentation in Wiki, coding guidelines.

- **Organizational decisions**
  - The architecture and documentation are designed for handover to future student groups, ensuring continuity across semesters.
  - Collaboration between **University of Augsburg** (software) and **AraCom IT Services GmbH** (hardware) is reflected in shared architecture planning and modular interfaces that separate hardware and software responsibilities.
