# 2. Architecture Constraints
<!-- Anything that constrains the team in design and implementation decisions or decision about related processes. Can sometimes go beyond individual systems and are valid for whole organizations and companies. -->

This section outlines the key constraints that limit design and implementation decisions, including technical, organizational, and political factors.


## Technical Constraints

| Constraint Category    | Constraints                                                                 |
|-----------------------|----------------------------------------------------------------------------|
| Hardware Compatibility | Must run on Jetson Nano, support the selected robotic arm and gripper, support the robot platform including omni-wheels, must support multiple sensors (RGB-D cameras, LIDAR) with reliable data acquisition |
| Real-time Capability   | Motion control, grasping, computer vision and safety-critical data must be processed in real-time; system reaction time for HRI must be acceptable |
| Power Management          | Must operate within available battery capacity; system must handle safe shutdown if battery is low |
| Network / Communication   | Reliable, low-latency communication between nodes for distributed computation |
| Modularity                | Components must be modular to allow easy upgrades or replacement without affecting overall system functionality |

---

## Organizational Constraints

| Constraint Category    | Constraints                                                                 |
|-----------------------|----------------------------------------------------------------------------|
| Programming            | Python & C++, Code commentation with google style                         |
| Experience / Resources | Limited experience with ROS2<br>Limited development time → preferred use of existing software components<br>Simulator limitations reduce testing possibilities |
| Team Knowledge            | Team members already familiar with behavior trees, motion planning, and SLAM |

## Conventions

| Constraint Category    | Constraints                                                                 |
|-----------------------|----------------------------------------------------------------------------|
| Knowledge Base         | Use of SQLAlchemy                                                          |
| Navigation / Movement  | Use of Nav2 & SLAM for navigation and mapping                               |
| Manipulation           | Use of MoveIt2 for motion planning                                         |
| Computer Vision        | Use of Yolo for image processing                                           |

## Safety Constraints (Specific)

| Constraint Category   | Constraints                                                                 |
|----------------------|----------------------------------------------------------------------------|
| Redundancy            | Safety must be ensured even if individual components fail                  |
| Safe Human Interaction| System must always operate safely around humans                            |
| Emergency Handling    | System must respond to sensor failures or unexpected obstacles appropriately |
| Emergency Stop         | Visible, red, easily pressable button only                                 |
