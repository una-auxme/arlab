# 10. Risks and Technical Debt

This document provides an overview of the key **technical risks** and **technical debt** in our robotic system.
It identifies potential problems across major system components — **Perception & Computer Vision, Knowledge Base, Manipulation, Movement, Safety, and Human-Robot-Interface (HRI)** — and describes mitigation strategies where possible.  

Each risk is assigned a **priority level** to support decision-making and planning:  

- **P1 (High)** – High impact and/or high likelihood, must be addressed as soon as possible.  
- **P2 (Medium)** – Moderate impact or likelihood, requires timely attention.  
- **P3 (Low)** – Low impact and/or low likelihood, can be monitored and resolved later.  

The risks are organized in tables by subsystem, making it easier for both the **development team** and **stakeholders** to understand critical challenges, track responsibilities, and prioritize actions.
This chapter aims to ensure transparency, guide project decisions, and reduce uncertainties in future development iterations.  

## Perception and Computer Vision

| Priority | Title | Risk Description | Suggested Measures |
| - | - | - | - |
| **P1 (High)** | High Quality Training Data | Good quality models as specified in the KPIs rely on high quality data. This data has to be found and in many cases segmented | • Consider semi-automated segmentation <br>• Find already segmented datasets. |
| **P1 (High)** | Resource-intensive | Running YOLO11 consumes significant computational resources. Real-time capability may suffer when balancing accuracy and available resources. | • Benchmark different YOLO11 sizes (Nano, Small, Medium, Large, XLarge).<br>• Start with YOLO11 Nano and scale up if resources allow. |
| **P2 (Low)** | Unknown frame detection rate | The exact performance of YOLO11 on Jetson hardware while running the full system is unknown. | • Evaluate model performance after system integration with real hardware tests. |

## Knowledge Base

| Priority | Title | Risk Description | Suggested Measures |
| - | - | - | - |
| **P1 (High)** | Real-time capability | The knowledge base is a central component. Frequent concurrent service requests may occur. | • Use async ROS callbacks and a reentrant callback group.<br>• Apply the custom AsyncIOExecutor for ROS scheduling on an asyncio event loop. |
| **P2 (Medium)** | Performance | Many modules rely on database information. High update and request frequencies could reduce performance. | • Monitor and benchmark under realistic workloads.<br>• Optimize database queries and schema where needed. |

## Manipulation

| Priority | Title | Risk Description | Suggested Measures |
| - | - | - | - |
| **P1 (High)** | Grasping objects with uneven weight distribution or complex shapes | Off-center mass or irregular shapes can cause tilting or slipping during lifts. | • Grip close to the geometric center and prefer top-down approaches.<br>• Lift slowly, pause briefly to stabilize, then move.<br>• Use sufficient grip force.<br>• Reset and use alternate grasp strategies if tilting is observed. |
| **P1 (High)** | Collision avoidance in tight environments | Small clearances can cause unintended contact with nearby items. | • Reduce movement speed near targets.<br>• Maintain ≥ 2 cm clearance and prefer top-down approaches.<br>• Stop briefly before placing, check surroundings, then lower. |
| **P1 (High)** | Precise determination of grasp points | Inaccurate grasp points reduce success rates and increase retries. | • Default to center of the visible surface.<br>• Capture a second short offset view if uncertain.<br>• Use predefined grasp points for known parts. |
| **P1 (High)** | Precise determination of placement points | Misaligned placements can cause overhangs or insertion errors. | • Align to clear references (marks, edges, stops).<br>• Lower slowly in the last ~5 cm.<br>• Release only when stable and visually confirm alignment. |
| **P1 (High)** | Hand closure completion | Grasping big objects with high closure rate grasps result in the hand never reaching the defined closure rate | • Stop trying to close the hand further after a set amount of time. |
| **P3 (Low)** | Failure detection | The robot could move or drop objects without detecting it during gripping them or placing them. | • Monitor hand forces while grasping the object. <br>• Accurate and reliable path planning is required to avoid colliding with objects that may be displaced during manipulation. |

## Movement

| Priority | Title | Risk Description | Suggested Measures |
| - | - | - | - |
| **P1 (High)** | Lack of real-world testing | So far, movement has only been tested in simulation. | • Perform staged real-world tests after integration of robot components. |
| **P2 (Medium)** | Behavior on different floor types | The robot may slip or stumble on different surfaces (e.g., concrete, wood, PVC, marble). | • Test on a representative set of floor types to identify potential issues. |
| **P2 (Medium)** | Localization drift | Wheel slips or collisions can cause localization drift. | • Introduce correction mechanisms such as sensor fusion or periodic recalibration. |
| **P2 (Medium)** | Headroom perception | LiDAR-only SLAM may not detect overhead obstacles, risking collisions. | • Add complementary sensors or extend SLAM algorithms to cover head height. |
| **P3 (Low)** | Energy efficiency | Limited battery capacity requires energy-efficient locomotion. | • Prioritize energy efficiency over speed or acceleration. |

## Safety

| Priority | Title | Risk Description | Suggested Measures |
| - | - | - | - |
| **P1 (High)** | Real-time capability | Slow detection can render safety responses ineffective. | • Define clear roles for decentralized safety checks and the global executor.<br>• Balance communication detail with response speed. |
| **P2 (Medium)** | Communication overhead | Extensive heartbeat communication may create bottlenecks. | • Evaluate communication load during integration tests.<br>• Optimize heartbeat frequency if necessary. |
| **P2 (Medium)** | Resuming processes after interventions | Resuming processes after a system-wide freeze is complex. | • Design and implement a robust multi-level safety mechanism.<br>• Validate the mechanism in dynamic scenarios. |

## Human-Robot-Interface (HRI)

| Priority        | Title                         | Risk Description                                                                      | Suggested Measures                                                                                         |
|-----------------|-------------------------------|---------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------|
| **P2 (Medium)** | Performance & RAM constraints | On the Jetson Orin Nano, HRI workloads may exceed latency and memory budgets.         | • Dedicate the Jetson Orin Nano exclusively to HRI.<br>• Use lean IPC with rate limiting and backpressure. |
| **P2 (Medium)** | Reliability                   | LLMs may hallucinate and provide incorrect answers without acknowledging uncertainty. | • Implement validation or fallback mechanisms to detect and mitigate hallucinations.                       |
